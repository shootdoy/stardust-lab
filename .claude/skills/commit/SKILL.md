# 커밋 스킬 — 스타더스트 랩용

지금 있는 변경을 **한 번의 커밋**으로 남긴다. 목표는 세 가지다.

1. **읽는 사람이 diff 를 안 봐도 «왜»를 알 수 있는 메시지**를 만든다
2. **이 프로젝트의 검증 절차**(dev/check.js · VERSION·BUILT 짝맞춤)를 커밋 전에 확인한다
3. **되돌리기 어려운 실수**(민감 파일 · --amend · --no-verify)를 애초에 못 하게 막는다

## 언제 트리거되나

- 사용자가 `/commit` 을 입력했을 때
- 사용자가 «커밋해줘» · «commit» · «커밋 남겨줘» 를 **명시적으로** 요청했을 때

작업 중에 «이쯤 되면 커밋 어때?» 같은 제안은 하지 않는다 — CLAUDE.md 의 «너무 능동적이지 않기» 원칙을 지킨다.

## 워크플로우

### 1. 현재 상태 파악 (병렬)

```bash
git status
git diff --staged
git diff
git log --oneline -5
git rev-parse --abbrev-ref HEAD
```

- 변경이 하나도 없으면 «커밋할 변경이 없다» 로 끝낸다. **빈 커밋을 만들지 않는다**
- 스타일은 최근 커밋 5개(`git log`)에 맞춘다 — 이 저장소는 **한국어 짧은 제목** 관례다
  (예: «편집 검증 하네스 — dev/check.js + 자동 훅»)

### 2. 스테이징

- **`git add -A` · `git add .` 금지.** `.env` · 사용자 QR 사진 등이 딸려갈 수 있다
- 파일을 하나씩 명시해 `git add <path>` 로 넣는다
- 이름에 `secret` · `token` · `.env` · `credentials` 가 들어간 파일이 있으면 **넣지 않고
  사용자에게 먼저 알린다**

이 프로젝트에서 스테이징 실수가 잦은 곳:
- `backup-v*.html` · `art_in/` · 잭의 실측 캡처 스샷 → 대개 커밋 대상이 아니다
- `src/` 의 소스를 고쳤으면 **그 소스와 `docs/index.html`(생성물) 을 함께** 넣는다.
  생성물만 넣으면 소스가 빠져 다음 빌드에 되돌아가고, 소스만 넣으면 배포물이 옛것이다

### 3. 검증 (index.html 을 고쳤을 때만)

`git diff --cached --name-only` 에 `src/` 나 `docs/index.html` 이 있으면 **커밋 전에** 확인한다.

⚠ **`docs/index.html` 은 생성물이다** (v3.52.0 · `src/` 10개를 `dev/build.js` 가 이어 붙인다).
소스와 생성물이 짝으로 담겼는지 보라 — `dev/sync.js` 가 다시 조립해 대조하므로
어긋나면 검사가 막지만, 스테이징에서 한쪽만 빠지는 것은 검사가 못 잡는다.

- `.claude/settings.json` 의 PostToolUse 훅이 이미 `dev/check.js` 를 돌려 뒀다 —
  훅이 exit 0 이었다면 통과다. 훅을 껐거나 못 미더우면 손으로 다시 돈다:

  ```bash
  node dev/check.js
  ```

- **VERSION·BUILT 짝맞춤** — CLAUDE.md 의 «버전 올리기» 절이 요구한다.
  기능이 바뀐 커밋이면 세 곳이 같은 값이어야 한다:
  - `<meta name="version" content="...">`
  - `const VERSION='...'`
  - `const BUILT='...'` (오늘 날짜)

  버전을 올려야 하는 커밋인데 안 올라가 있으면 사용자에게 먼저 알린다 —
  자동으로 올리지 않는다. 어떤 값으로 올릴지는 잭이 정한다.

### 4. 커밋 메시지 초안

**Conventional Commits** 형식이되, 이 저장소의 관례에 맞춘다.

```
<type>: <한국어 제목 — 간결하게>

<본문 — 왜 이 변경을 했는가. 없이도 이해되면 생략>
```

**type 후보**: `feat` · `fix` · `refactor` · `docs` · `chore` · `perf` · `test` · `revert`

이 저장소에서 자주 쓸 만한 것:
- 데이터/규칙 변경: `feat` (예: `feat: 대기 피격 곡선 반영`)
- 버그 수정: `fix` (예: `fix: hEditIdx 앵커가 세 곳에 중복 붙던 버그`)
- 문서: `docs` (CLAUDE.md·notes/ 만 바뀐 경우)
- 스크립트/훅: `chore` (dev/ 도구)

**제목 규칙**
- **60자 이내**, 명령형, 마침표 없음
- «index.html» · 파일명을 제목에 박지 않는다 — 무엇을 바꿨는지가 먼저다
- scope 는 생략해도 된다 (단일 파일 저장소라 의미가 얕다). 정말 필요할 때만
  `feat(damage): …` 처럼 붙인다

**본문 규칙** (필요할 때만)
- 산문 또는 불릿(`- `). 무엇을 어떻게 바꿨는지가 diff 로 명백하면 **왜** 만 적는다
- 실측 표본·잭 지정 사항이 근거면 그것을 남긴다 («잭 지정 2026-08-22»·«실측 3건»)
- 되돌린 결정을 남길 때는 이유를 짧게 (예: «v3.31.0 의 판 자동 교대는 교대 전제가 틀렸다»)
- 파일 목록 나열 금지 — `git show --stat` 에 이미 있다

### 5. 사용자 확인

초안을 화면에 보여주고 **명시적 승인**을 받는다. 승인 없이 커밋하지 않는다.

```
[커밋 메시지 초안]
─────────────────────
feat: 대기 피격 곡선을 f^0.39 로 재적합

실측 12건에서 √f(RMS 11.8%)보다 f^0.39(9.2%)가 잘 맞았다.
같은 대상 가이오가 쌍(f 90→377, 피해 1.35배)이 √f 를 직접 반증한다.
─────────────────────

이대로 커밋할까요? (수정할 곳이 있으면 알려주세요)
```

### 6. 커밋 실행

**반드시 HEREDOC** 로 넘긴다 — 줄바꿈과 특수문자가 안전하다.

```bash
git commit -m "$(cat <<'EOF'
feat: 대기 피격 곡선을 f^0.39 로 재적합

실측 12건에서 √f(RMS 11.8%)보다 f^0.39(9.2%)가 잘 맞았다.
같은 대상 가이오가 쌍(f 90→377, 피해 1.35배)이 √f 를 직접 반증한다.
EOF
)"
```

- 완료 후 `git status` 로 확인한다
- **pre-commit 훅이 실패하면**: 커밋 자체가 안 만들어졌으므로 **새 커밋**을 만든다.
  `--amend` 는 금지 — 훅 실패 상태에서 amend 하면 **직전 커밋을 덮어써 작업이 사라진다**
  (CLAUDE.md 의 «편집 사고 이력» 과 같은 부류다)

### 7. push 는 하지 않는다

사용자가 «푸시해줘» 를 별도로 말했을 때만 `git push` 한다.
`main` 에 대한 force-push 는 사용자가 명시적으로 다시 요구하지 않는 한 절대 하지 않는다.

## 금지 사항

| 금지 | 이유 |
|---|---|
| `git add -A` · `git add .` | 실측 캡처·백업본·시크릿이 딸려간다 |
| `git commit --amend` | 이 저장소는 «편집 사고 이력» 이 두 번 있었다. 새 커밋이 안전 |
| `git commit --no-verify` | 훅이 걸린 이유는 CLAUDE.md 의 «편집 원칙» 이다. 훅을 우회하지 않는다 |
| `git commit --no-gpg-sign` · `-c commit.gpgsign=false` | 사용자 요청 없이 서명 우회 안 함 |
| `Co-Authored-By: Claude …` 자동 삽입 | 잭이 원하면 그때 넣는다. 기본은 안 넣는다 |
| 사용자 확인 없는 커밋 | 항상 초안을 보여주고 승인 받는다 |
| 빈 커밋 (`--allow-empty`) | 요청받지 않는 한 만들지 않는다 |

## 이 저장소 특유의 주의점

- **단일 `index.html`** 을 배포한다. `index.html` 이 바뀌었는데 VERSION 이 그대로면
  «버전을 올려야 하는 커밋인가?» 를 사용자에게 물어본다
- **`dev/sync.js`** 는 문서와 코드가 어긋나지 않는지 감시한다. `dev/check.js` 가 이를 부른다 —
  훅이 통과했으면 통과다
- **아트 삽입** (`artgen.py --write`) 뒤에는 `TAGIMG_N`·`LOW_N` 을 함께 올려야 sync 가 통과한다.
  그 편집 자체가 «조용한 미저장» 을 유발할 수 있으므로 (`notes/machine.md` 근처 CLAUDE.md 참고),
  이 커밋을 만들 때 파일 크기와 키 수를 한 번 더 확인한다
- **커밋 메시지는 한국어.** 이 저장소의 모든 커밋 이력이 그렇다

## 예시

### 좋은 예 — 규칙 변경

```
feat: 여파 계산을 대상별로 나눈다

v3.17.0 은 활성 피해를 대기 전원에게 그대로 복사했는데,
그러면 상성·방어가 활성 상대 것이라 보스와 다른 서브가 같은 값을 받는다.
대기 대상 각각의 f 로 다시 계산한다.
```

### 좋은 예 — 짧게 끝나는 커밋

```
docs: notes/machine.md 로 배급 연구 노트를 분리
```

### 나쁜 예

```
update index.html                     ← 무엇을·왜 가 없다
fix bug                                ← 무슨 버그
feat(index): change stuff              ← scope 가 파일명
[Claude] 자동으로 여러 파일 커밋       ← 사용자 확인 없이 뭉텅이
```
