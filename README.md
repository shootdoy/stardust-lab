# 스타더스트 랩

포켓몬 **태그스타** 아케이드 게임의 보스 공략 도구. 보유한 태그를 등록해 두면
타입 상성과 스탯으로 **3턴 로테이션**과 **서포트 티켓**을 추천한다.

**→ https://shootdoy.github.io/stardust-lab/**

> 개인이 만든 **비공식** 팬 도구다. 포켓몬 및 관련 표장은
> Nintendo · Creatures · GAME FREAK 의 것이며 이 프로젝트와 아무 관계가 없다.
> 게임 내부 수치는 공개된 적이 없어, 여기 계산은 **카드 뒷면 실측과 플레이 관측에
> 근거한 추정**이다.

---

## 무엇을 하는 도구인가

기계에 넣을 태그를 고르는 일은 **타입 상성 · 스탯 · 기믹 제약**이 한꺼번에 얽혀서
머리로 풀기 번거롭다. 이 도구는 그 계산을 대신한다.

| 화면 | 하는 일 |
|---|---|
| **플레이** | 보스를 고르면 낼 태그 3장과 순서, 서포트 티켓을 추천한다 |
| **컬렉션** | 가진 태그를 등록한다. 수집 도감도 여기 있다 |
| **설정** | 룰렛 보정값·상대 태그 탄·기록 기능을 조절한다 |
| **기록** | 판마다 상대·선물·결과를 남긴다 (설정에서 켤 때만 보인다) |

반영하는 규칙은 이렇다.

- **타입 상성** 18타입 전체 (본가 2배 기준 — 실측으로 확인)
- **탈진** 직전 턴에 쓴 태그는 다음 턴에 못 쓴다
- **기믹 1회** 메가진화 · Z기술 · 다이맥스는 배틀당 각 한 번
- **찬스 보너스** 룰렛·기술 판정으로 붙는 공격 보정 (기믹마다 기대값이 다르다)
- **배틀 모드** 지역배틀(3vs3) · 다이맥스 포켓몬(1vs3) · 스페셜태그배틀(1vs6)

3턴 조합은 탐욕이 아니라 **완전탐색**으로 고른다. 기본 모드는 받는 피해까지 함께
보는 «밸런스» 이고, 화력만 보는 «최대 화력» 을 따로 고를 수 있다.

⚠ 화면의 «예상 피해» 는 **HP 감소량이 아니다.** 게임 공식이 비공개라 같은 보스
안에서의 **비율**로만 쓸 수 있다. 보스가 바뀌면 방어 수치가 분모라 기준이 흔들린다.

## 구조

**산출물은 `release/index.html` 한 벌뿐이다.** 태그 아트 146장 · 타입 아이콘 18개 · 폰트
서브셋까지 전부 base64 로 내장돼 있어, 파일 하나를 정적 호스팅에 올리면 끝난다.

```
release/index.html   배포물. 이것이 앱 전체다 (851KB) — GitHub Pages 가 이 폴더를 서비스한다
dev/            검증·분석 도구 (Node · Python)
.claude/        작업 스킬과 훅 설정
```

외부로 나가는 요청은 **구글 애드센스**와 **GA4** 둘뿐이다. 그 외에는 서버가 없다 —
보유 태그·도감·기록은 모두 브라우저 로컬 저장소에 있고 운영자가 볼 수 없다.
자세한 것은 앱의 «설정 → 개인정보 안내» 에 적혀 있다.

**base64 는 CSS 에만 넣는다.** 시작할 때 `<style>` 하나에 `.aNN{--art:url(...)}`
꼴로 한 번만 심고 요소는 클래스로 참조한다. DOM 에 직접 인라인하면 같은 데이터가
수백 번 복제돼 렌더가 두 배 가까이 느려진다 (실측 337ms → 177ms).

## 개발

빌드가 없다. `release/index.html` 을 직접 고치고 브라우저로 열면 된다.

### 검증

**고친 뒤에는 반드시 하네스를 돌린다.**

```bash
node dev/check.js          # 다섯 검사 (2초 안팎)
node dev/check.js --quick  # undef · interact 만
```

| 검사 | 무엇을 잡나 |
|---|---|
| `undef` | 호출되지만 정의되지 않은 식별자 |
| `interact` | 가짜 DOM 에 올려 모든 클릭을 발화 |
| `fixture` | 기준 컬렉션으로 규칙 위반 (기믹 중복·탈진) |
| `glyph` | 제목이 서브셋 폰트에 없는 글자를 쓰는지 |
| `sync` | 문서에 적힌 내용이 실제 코드에 있는지 |

`.claude/settings.json` 의 PostToolUse 훅이 **`index.html` 이 바뀔 때마다 자동으로**
이것을 부른다. 실패하면 그 자리에서 막고 원인을 보여 준다.

**문법 검사만 통과해도 안심하면 안 된다.** 정의가 사라져도 문법 오류가 아니라서
실행해야 터진다. 실제로 이 파일을 고치다 코드를 두 번 날렸고, 그래서 하네스가 있다.

### 그 밖의 도구

```bash
node dev/best-a25.js       # 우선 확보 태그 재계산 (규칙·데이터가 바뀔 때만)
node dev/damage.js         # 실측 표본으로 데미지 공식 검증
python3 dev/artgen.py <폴더> --write   # 태그 아트 삽입
python3 dev/dexcrop.py <캡처> <이름>…  # 도감 캡처에서 카드 잘라내기
```

### 버전 올리기

`index.html` 의 **세 곳**을 같은 값으로 고친다. 하나라도 어긋나면 앱의 «새 버전»
알림이 안 떠서 사용자가 옛 화면에 갇힌다.

```
<meta name="version" content="…">
const VERSION='…'
const BUILT='…'        ← 오늘 날짜
```

### 용량

`dev/sync.js` 가 **900KB** 를 상한으로 감시한다 (현재 785KB). 태그 아트가 대부분이라,
넘칠 것 같으면 아트 재압축이 먼저다. 3탄 데이터가 들어오면 아트 외부 분리를 검토해야 한다.

## 배포

GitHub Pages 가 **`main` 브랜치 루트**에서 서비스한다. 곧 **`main` 에 머지되는 순간
배포된다.** 그래서 작업은 브랜치에서 하고 PR 로 올린다.

배포 뒤 «예전 화면이 그대로 나온다» 는 iOS 홈 화면 웹앱의 캐시 때문이다.
GitHub Pages 는 커스텀 헤더를 걸 수 없어, 앱이 스스로 자기 URL 을 `no-store` 로 받아
버전을 비교하고 새 버전 알림을 띄운다. **이것이 유일한 수단이다.**

## 데이터

카드 뒷면 · 공식 포스터 · 도감 화면을 **실측**해 넣었다. 추정치는 없다.

| 구분 | 수 |
|---|---|
| ★6 · ★5 (1·2탄) | 50 |
| 레귤러 · 스페셜 (탄 공통) | 6 |
| ★4 이하 (상대 서브·전투용) | 90 |
| **태그 아트** | **146장** |
| 보스가 될 수 있는 것 | 53종 |

- ★6·★5 50장은 카드 뒷면으로 **전량 재검증**했다 (에너지 · 6스탯 · 기술 · 타입 · 기믹)
- 검산 규칙은 **에너지 ≈ 6스탯 합 ÷ 5**. 허용 편차는 성급마다 다르다 —
  저성급은 원래부터 흩어짐이 크다
- ★4 이하는 **기술 위력이 미표기**라 기본값으로 계산된다. 그 묶음의 예상 피해와
  판정은 ★5·★6 만큼 믿을 수 없고, 화면에도 그렇게 적어 두었다

## 저장소에 없는 것

작업 지침(`CLAUDE.md`) · 연구 노트(`docs/`) · 실측 원자료(`data/`) 는 **일부러 넣지
않았다.** 공개 저장소이고, 그 내용은 개인 플레이 기록과 관찰이라 여기 둘 것이 아니다.

그래서 이 저장소만 클론하면 **앱과 도구는 온전하지만 설계 배경은 없다.**
계산 근거가 필요하면 앱 화면의 안내 문구에 요지가 적혀 있다.

문의해 주면 좋겠다.
